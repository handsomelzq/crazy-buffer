# Crazy Buffer：最小版本需求与技术设计

日期：2026-10-20

状态：用户于 2026-10-20 确认当前方案，允许逐步推进并使用多 agent。已确认 API 优先、第二版 GUI 的方向与最小范围；具体实施细节记录在实施计划。尚未实现、安装依赖或验证性能。

## 1. 项目定位与已确认方向

第一版为熟悉 GIS 分析流程、能够编写 Python 的研究者提供本地、轻量、可复现的空间计算库。用户在脚本或 Notebook 中组合函数、插入自己的数据清洗和统计步骤，获得指标表、可检查的空间结果、质量报告和计算记录。项目未来在 GitHub 开源。

用户最新明确：第一版先跑通底层能力，提供可自由编排的接口；第二版再建设快速操作的 GUI，面向 GIS 和 Python 初学者。此方向替代此前“配置文件 + CLI”为主要入口的设想。第一版采用 Python API + Notebook 案例，不强迫用户理解 JSON 配置或命令行任务协议。仍然先平面计算、后路网计算，且不堆功能。

“自由编排”指普通 Python 函数与 DataFrame 能够组合，允许过滤、分组、循环、合并和接入用户自己的代码；不意味着第一版开发工作流 DSL、可视化拖拽或任务调度平台。第一版的两个研究案例用于验证接口，不限定用户只能运行这两条固定流程。

ArcGIS/QGIS 本身也能通过脚本、模型和处理历史实现复现。此项目的价值是为常见研究问题提供更容易分享、审核和重跑的统一约定，而不是宣称 GUI 工具无法复现。

## 2. 第一版范围

### 必须提供的基础能力

| 能力 | 最小实现 | 验收要求 |
| --- | --- | --- |
| 数据导入 | 接收内存中的 GeoDataFrame；提供点 CSV、GeoPackage 读取辅助函数 | 不强迫已有 Python 工作流重新写文件；保留稳定 ID，显式声明坐标字段及 CRS |
| 参数接口 | 类型明确的 Python 参数，包含半径、字段、分析 CRS、单位等 | 默认值有文档；非法参数报错；不要求 JSON 配置 |
| 输入校验 | 几何类型、空几何、有效性、CRS、坐标范围、ID、统计字段类型 | 数据集级错误停止；要素级问题默认停止并生成问题明细；仅在显式选择跳过后排除并记录 |
| 可组合计算接口 | 准备数据、邻域匹配、属性聚合、最近距离分别可调用；提供常用组合的便捷函数 | 用户可读取中间结果并插入自己的步骤；便捷函数与分步计算结果一致 |
| 结果导出 | CSV 指标表；GPKG 空间结果；JSON 运行清单和质检摘要 | 保留输入对象 ID；每个对象的状态可解释；失败不伪装成零值 |
| 可复现记录 | 显式记录输入快照、函数参数、软件版本、分析 CRS、用户脚本和处理数量 | 不依赖固定 runner 才能记录；区分库内计算与用户自定义步骤 |
| 基础发布质量 | 合成示例、自动化正确性测试、README、锁文件 | 新环境可以离线运行已安装项目的示例；联网只用于安装或显式获取数据 |

### 用两个案例验证少量可组合能力

1. **`buffer_stats`**：点或面对象，在单一半径范围内统计目标点的数量及指定数值字段的均值。示例为公园 AOI 周边 1500 m 的住房样本单价均值。
2. **`nearest_distance`**：起点到目标点的最近平面直线距离，输出目标 ID 和距离。示例为住宅点到地铁站点或入口点。

两类案例分别验证“空间邻域聚合”和“最近邻查询”链路。`buffer_stats` 是邻域匹配与属性聚合的便捷组合，不是唯一可调用入口；底层的匹配关系、统计和缓冲几何也能单独获取。所有新增接口仍服务这两个案例，不扩大到更多指标。

### 暂缓功能

| 后续能力 | 延后原因 | 现阶段如何预留 |
| --- | --- | --- |
| 内置多尺度批跑 | 先验证单尺度正确性，再复用索引优化 | 半径为函数参数；用户可自行用 Python 循环，暂不提供批跑引擎 |
| 密度 | 需要明确面积分母及边缘修正 | 保留计数，未来新增明确口径的 density 任务 |

| 环带、外侧缓冲、中心点/入口模式 | 各自代表不同研究问题 | 第一版固定完整几何缓冲，其他模式后续显式增加 |
| 步行距离、等时圈、2SFCA、重力可达性 | 路网拓扑、接入误差与供需模型需要独立设计 | 未来新增 network 模块和可选依赖 |
| 栅格人口、土地覆盖、核密度 | 涉及新数据类型和统计规则 | 第一版仅矢量；保留数据源清单供后续使用 |

| CLI、JSON 任务协议、在线地图、报告生成 | 当前没有必要成为第一版门槛 | 有明确需求后增加薄封装，不反向约束核心 API |
| 缓存、数据库、多进程、分布式 | 在实际瓶颈出现前增加维护负担 | 函数边界清晰，第一版串行执行 |

## 3. 科学计算契约

### 缓冲范围内统计

- 对点或 AOI 的完整几何计算距离；不把面默默替换为质心。面内点距离为零，纳入完整缓冲范围；多面和孔洞保留。
- 统计判定采用“到原始几何的平面距离 ≤ 半径”。空间索引先筛选候选，再做精确几何距离判断，避免导出的 buffer 圆弧离散近似改变临界点归属。
- buffer 几何用于空间结果导出；固定并记录圆弧离散精度。导出多边形是理想缓冲范围的近似，方法说明中明确这一点。
- 每个公园独立统计；同一个住房点可以进入多个公园的邻域。不默认去重不同公园的重叠范围。
- 输出 `source_id`、`radius_m`、`n_matches`、`n_valid_values`、`mean_value`、`status`。没有邻域点时 count 为 0，mean 为空；存在点但数值全部缺失时均值仍为空，状态不同。
- 空数值可排除但必须计数；无法解析的数值、无穷值须报告。不会因几何重合而擅自删除不同 ID 的住房记录。
- 房价需声明单位及记录含义，例如元/平方米、楼盘挂牌均价、采集日期。默认算术平均代表所提供样本记录的平均值，不能自动解释为市场总体或成交均价。用户负责选择可比较的样本时间与单位，程序校验声明和字段，不从数值猜测。

### 最近直线距离

- 第一版限定点到点，采用投影平面距离，结果单位为米；不声称是球面距离、步行距离或到地铁站台的实际行程。
- 目标可以是站点中心或入口，但必须在数据说明及运行元数据中注明；有入口数据时可以研究到最近入口的距离。
- 输出 `source_id`、`target_id`、`distance_m`、`tie_count`、`status`。
- 第一版在计算得到的最小距离相等时，按唯一目标 ID 的稳定字典序选择一个，并记录并列数量；不依赖输入顺序。数值比较规则及测试容差与软件版本一起记录。
- 起终点重合时距离可以为零；空目标数据集应停止并报错，不能为所有起点填零。

### 坐标与数据质量

- 所有输入要有已知 CRS；CSV 必须声明原始坐标系。分析 CRS 由函数参数明确指定，必须适合研究区并采用米制单位。
- 第一版不自动选择或推断 CRS。北京小范围分析可在确认原始基准与区域后采用合适的 UTM 或高斯投影；不固定所有中国城市使用一个 EPSG，也不默认用 Web Mercator 计算科研距离。
- `set_crs` 是声明，`to_crs` 才是转换；不能通过改标签消除偏移。
- GCJ-02、BD-09 不是普通 EPSG 重投影能自动解决的坐标偏移。第一版识别声明后拒绝直接混算，要求先提供已统一且有转换来源记录的数据。
- 无效几何不静默修复；原文件不修改。后续修复功能也应写新文件、记录修复和排除对象。
- 研究区边缘缺少区外 POI 时，应给出数据覆盖提醒；不能把缺失覆盖视为真实的零设施。第一版要求记录数据覆盖范围，但不宣称能自动验证数据完整性。

## 4. 技术方案与取舍

推荐 Python 3.12、uv 管理环境，GeoPandas + Shapely + pyproj + pyogrio 构成计算与 I/O 基础。以可导入的 Python 包提供公开 API；Notebook 和测试工具作为开发/示例依赖，普通脚本无需安装 Jupyter。第一版不要求开发 CLI 或配置解析器。

| 方案 | 结论 |
| --- | --- |
| Python 本地分析包 | 推荐。贴近研究者已有工作方式，易于解释、复核和测试 |
| DuckDB Spatial / PostGIS | 目前不加入。以后有实测容量瓶颈、SQL 需求或共享数据库需求时再评估 |
| QGIS Processing 封装 | 适合已有 QGIS 用户，但引入桌面软件及其环境依赖，不作为默认分发方式 |

不自写几何引擎，也不一次引入 PySAL 全家桶。空间索引利用成熟库；业务层负责明确契约、校验、编排与可复现输出。

建议结构（尚未创建代码骨架）：

`operations` 提供可独立组合的计算，`recipes` 组合已有操作，`api` 提供稳定的公开导入位置，`io` 负责文件读写，`provenance` 负责计算记录。第一版不需要中央任务路由或动态插件系统。

计算接口接受 GeoDataFrame 和显式参数，返回 DataFrame/GeoDataFrame；匹配关系采用稳定的 `source_id`、`target_id`、`distance_m` 列，避免使用易变的行号。聚合时显式传入完整起点集合，以保留零匹配对象。空间结果保留 CRS，结果元数据和质检作为独立对象传递，不只藏在容易丢失的 DataFrame.attrs 中。

所有公开接口自行检查输入契约，不能仅依赖“用户之前应该调用过 prepare”。函数不修改传入数据、不隐式联网、不隐式写文件，不依赖全局变量或界面状态。公共参数采用米等明确单位；质检错误携带错误码、字段和对象 ID，方便第二版 GUI 展示。

## 5. Python 编排工作流与接口示意

推荐流程：读取或传入已有数据 → 用户清洗/筛选 → 校验并统一坐标 → 调用计算接口 → 自定义聚合/合并 → 显式导出与记录。用户可以在任意步骤读取中间表，不需要先把分析表达成配置文件。

以下仅为拟定 API 示意，尚未实现；`parks` 和 `housing` 假定已经校验并转换到同一个适合研究区的米制投影，且保留唯一 ID。

```python
from crazy_buffer import buffer_stats, neighbors_within, summarize_neighbors

# 常用案例：一次调用得到公园周边住房样本的数量和均值。
result = buffer_stats(
    parks, housing,
    source_id="park_id", target_id="housing_id",
    radius_m=1500, value_column="price_per_m2",
)

# 自由编排：先取得空间关系，再检查或组合自己的处理步骤。
links = neighbors_within(
    parks, housing,
    source_id="park_id", target_id="housing_id",
    radius_m=1500,
)
result = summarize_neighbors(
    links, sources=parks, targets=housing,
    source_id="park_id", target_id="housing_id",
    value_column="price_per_m2",
)
```

`neighbors_within` 返回匹配表；`summarize_neighbors` 使用匹配表和目标属性做 count/mean，保留完整起点集合。用户可以直接用 Pandas/GeoPandas 操作这些数据；自行过滤匹配表会改变统计口径，必须在研究脚本和运行说明中记录。`buffer_stats` 与未经额外处理的分步调用在相同口径下应得到一致结果。缓冲几何可以由单独的 `make_buffers` 获取；`nearest_distance` 单独提供点到点最近距离。

为控制第一版体积，不开发通用工作流引擎。代码循环、条件筛选和 DataFrame 合并由 Python 本身承担。常见组合保存在示例脚本与 Notebook，用户可以复制、调整和版本管理。

输入输出分离：API 调用返回内存结果；只有用户显式调用导出辅助函数才写文件。导出目录已存在时默认拒绝覆盖。标准导出包括 `results.csv`、按需生成的 `results.gpkg`、`quality.json`、存在问题时的 `issues.csv`、`run_manifest.json`。导出采用临时目录，成功后再形成完整目录；直接调用 API 的异常交由调用者处理，不冒充已完成的任务。

运行记录由独立辅助接口创建，不依赖特定 runner：用户传入输入来源、分析脚本、操作及参数记录、最终结果与质检信息。文件输入记录 SHA-256；内存输入可以显式保存为新的输入快照并计算哈希，不覆盖原始数据。库内操作记录算法、参数和软件版本；用户自行执行的 Pandas 清洗或第三方处理无法被库自动完整捕获，必须保存脚本/Notebook、相应输入快照和说明。元数据不足时将复现状态标为不完整，不声称仅凭最终结果就可复现。

运行清单至少包含：输入快照和脚本哈希、调用参数、包及算法版本、可得的 Git 提交号、Python/依赖/GEOS/GDAL/PROJ 版本、分析 CRS、数据处理数量、告警及输出文件哈希。输出与运行元数据的自身哈希不形成循环依赖。标准结果不依赖私有对象序列化，后续 GUI 可以将表单参数和上传数据转成同样的 API 输入，并导出对应 Python 脚本。

可复现承诺是相同输入、处理逻辑和参数得到容差内一致的指标，不承诺跨系统 GeoPackage 文件字节完全相同。第一版示例为本地合成数据，计算过程不依赖在线服务。

## 6. 性能与资源边界

默认串行，不构造全量起点×目标点距离矩阵。便捷统计函数按起点分批查询并及时聚合，不要求一次保留全部匹配关系；用户显式调用 neighbors_within 则会取得关系表，结果规模可能显著大于输入，必须提供可配置的匹配数量上限并在超限时报错，不能静默截断。两条路径复用相同的匹配与聚合语义。

分批并不意味着无限内存能力：目标数据及空间索引通常仍在内存中。框架稳定后再对 1 万/10 万目标点及不同 AOI 复杂度做分级基准，记录环境、时间与峰值内存，不预先许诺“百万点秒级”。

本机 8GB 内存，重计算前遵守 `~/bin/memcheck.sh` 约定；不安装依赖或启动重任务，除非已获用户授权。Notebook 包含用户分析编排、API 调用和结果解释，通用算法放在包内，重计算由用户本地执行；开发过程以语法检查和小型正确性测试为主。

## 7. 最小验收与开源交付

1. 人工可计算案例：少量公园与住房点能手算出计数和均值；包括面内部、孔洞、多面、恰好在阈值上、阈值内外的点。
2. 最近邻案例：已知坐标的距离、重合点、等距目标与空目标；输入顺序变化不改变选定规则。
3. 异常案例：缺失 CRS、重复 ID、非法 API 参数、错误单位、非法几何、缺失值、不可解析价格及匹配数量超限。
4. 流程案例：分步 API 与便捷函数结果一致；内存数据与文件读取结果一致；函数不修改输入；用户可过滤、聚合、合并中间表；导出失败不留下成功标记的半成品，已有结果不被覆盖；内存快照和脚本足以重跑示例。
5. 首次公开稳定版前，在 Windows/macOS/Linux 的全新环境中验证安装和两个例子；小样本与 QGIS 同等 CRS/口径结果交叉核对。以手算和边界测试为主要正确性证据。
6. GitHub 包含 README 快速开始、指标定义、合成数据说明、代码 LICENSE、单独的数据许可、贡献指南和基础 CI。代码许可证建议 MIT，正式采用前确认；上游数据许可不因代码使用 MIT 而改变。
7. 用户真实数据、密钥、运行结果、缓存不进入仓库。引用元数据可采用 CITATION.cff；版本发布后可再通过 Zenodo 归档，不作为第一版启动前提。

实施拆成两个短阶段：先让数据契约、校验、空间匹配、聚合、输入输出和运行记录贯通，并以分步调用与 `buffer_stats` 验证；再加入 `nearest_distance`、Notebook 和测试。框架完成不能仅以目录存在为验收，必须能运行至少一个有预期答案的完整小案例。

## 8. 第二版 GUI 与后续计算能力

### 第二版：面向初学者的快速操作平台

第一版稳定后，第二版提供引导式 GUI：选择案例/指标 → 导入文件 → 选择图层和字段 → 检查坐标与数据质量 → 填写距离等参数 → 预览与执行 → 下载结果、质检和可复现脚本。初学者无需输入 Python、命令或 JSON，也不应被要求盲选 EPSG；界面应解释检测到的坐标信息与可选投影，对无法确认的来源要求补充信息，不能静默猜测。

GUI 作为 API 的薄调用层，复用第一版的参数校验、错误信息和算法。第一轮 GUI 只覆盖已稳定的计算能力；不需要同时增加路网、账户系统、云存储或拖拽编排。部署优先评估本地运行，具体界面技术和打包方式在第二版设计时决定。

第二版的可视化/易用性与后续路网扩展是两条独立方向，不将“有 GUI”等同于“已支持步行可达性”。

### 后续：路网计算扩展

后续以 OSMnx + NetworkX 为可选依赖，先支持已具有可靠拓扑的图。任意道路 Shapefile 自动建图属于独立功能，需要处理立交、断线、步行权限和连接关系。

“先接入主路，再沿主路”是主路约束模型，不等同于真实步行。实际步行还受支路、步道、围墙、河流、入口及通行规则影响。更稳妥的结果名称是“基于路网的估计步行距离”，并分别输出接入、路网与离网段距离。

正式步行模块应设计最近可用边接入和边分割，而非直接把点移到最近节点；需要最大接入距离和不可达状态。直线最近的站未必是网络最近的站，应面向所有合法目的地计算；大量起点可以采用多源最短路。有向图的搜索方向必须正确。无路时不得用直线距离填补。

## 9. 开放数据来源与获取边界

以下是候选目录和选型依据，不是已下载、验收或可随仓库分发的数据包。2026-10-20 本轮成功检索了部分技术官方文档，但数据许可页的实时读取因连接/审批服务异常未完成。以下许可摘要需在实际选定具体版本时回读确认，尤其不能用平台名称代替具体数据集授权。

| 来源 | 可支持的分析 | 许可与可用性边界 |
| --- | --- | --- |
| [OpenStreetMap](https://www.openstreetmap.org/copyright) / [Geofabrik 中国下载](https://download.geofabrik.de/asia/china.html) | 公园 AOI、步行道路、建筑、地铁入口候选 | OSM 通常按 ODbL 提供，署名与派生数据库义务须遵守；北京具体区域完整性及标签质量未核验。Geofabrik 是同源分发，不是独立数据源 |
| [北京市公共数据开放平台](https://data.beijing.gov.cn/) | 本地公共设施、交通等政府数据检索入口 | 目前只是目录入口，未核实具体公园面、入口点或房价文件；按数据集确认下载条件和再分发许可 |
| [WorldPop](https://hub.worldpop.org/) | 人口栅格、缓冲范围内人口估计 | 常见产品采用 CC BY 4.0，仍须核对具体产品。模型人口不是逐户实测；年份、栅格含义及分辨率需匹配 |
| [GHSL](https://human-settlement.emergency.copernicus.eu/download.php) | 人口、建成区、聚落分类 | 全球产品候选；依具体产品复用规则引用。建成表面不等于建筑轮廓或层数 |
| [ESA WorldCover](https://esa-worldcover.org/en/data-access) | 土地覆盖、绿地或建成区比例 | 全球 10m 产品候选，常见版本采用 CC BY 4.0；确认年份和许可。树木/草地类别不是公园管理边界 |
| [北京市统计局](https://tjj.beijing.gov.cn/) | 人口与社会经济统计、聚合结果对照 | 公开统计资料，不等同于开放许可的逐点数据库；区域匹配及使用条件另核对 |
| [高德地点检索](https://lbs.amap.com/api/webservice/guide/api/search) / [百度地图平台](https://lbsyun.baidu.com/) | 用户授权取得的 POI、路线等可选输入 | 商业 API，不是开放数据；配额、保存和再分发受协议约束；当前条款未核验，不作为默认公开样例数据 |

北京逐点房价：本轮没有核实到稳定下载且明确允许公开再分发的来源。不能由此断言不存在；也不能把链家/贝壳网页、第三方爬取 CSV 或 GitHub 附件直接视为开放授权数据。第一版用明确标注的合成房价和合成几何完成案例；后续允许用户导入合法取得的数据。

每份用于研究的数据应另存数据卡：来源 URL、获取日期、数据年份、许可、覆盖范围、坐标系、字段单位、清洗规则、文件哈希。获取数据与计算指标分离；快照固定后可以离线重跑。历史论文不能无说明地用最新路网替代研究年份路网。

## 10. 官方技术依据与核验状态

- [OSMnx 官方文档](https://osmnx.readthedocs.io/en/stable/)：本轮官方检索结果确认街道网络建模、分析和路径相关能力；具体版本/API 尚未在本机执行验证。
